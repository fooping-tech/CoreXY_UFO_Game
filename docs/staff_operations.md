# スタッフ操作（#260）

展示中のスタッフが、どの画面でも同じキーで「次へ進める・飛ばす・メニューへ戻す・復帰させる」をするための操作。画面ごとの意味は下の表のとおり。

操作は名前付きの「スタッフ操作」として `game/scripts/game/staff_control.gd`（`StaffControl`）の 1 か所にまとまっている。キーボードも、あとで足す外部デバイス（ボタン・リモコンなど）も、`StaffControl.run(操作名, 送り元)` を呼ぶだけで同じことができる。`describe(操作名)` は、今の画面でその操作が何をするかを短い言葉で返す（何もしないときは空）。外部デバイスのボタンの表示や、スタッフ向けの表示に使う。

## 操作とキー

| 操作 | キー | 意味 |
|---|---|---|
| `next`（次へ） | F6 | 今の画面の一歩を進める。待ちは飛ばす |
| `skip`（スキップ） | F7 | まとめて飛ばす |
| `menu`（メニューへ） | F8 | メニュー（タイトル）へ戻る |
| `recover`（復帰） | F9 | アラーム解除 → まとめて準備（アームが動く）。かんたんモードの停止も戻す |
| `switch`（切り替え） | F10 | 学習モード ⇔ ゲーム |
| `stop`（停止） | Space | 止める。いつでも優先 |

Shift を押しながらの F6〜F8 は、開発者用の元の機能（練習のステップのやり直し、学習モードの失敗の注入・最初から）。

## 画面ごとの意味

| 画面 | F6 次へ | F7 スキップ | F8 メニューへ | F9 復帰 | F10 切り替え |
|---|---|---|---|---|---|
| 設定・校正（起動直後） | メニューへ（保存しないで閉じる） | 同じ | 同じ | アラーム解除 → まとめて準備 | 学習モードへ |
| メニュー（タイトル） | 選んでいるものを始める | 同じ | — | 同上 | 学習モードへ |
| 学習モード | 読み込み・採点などの待ちを飛ばして続ける（ごほうびの画面ではゲームへ） | 勉強を終えてゲームへ | メニューへ | 同上 | ゲームへ |
| スコアゲームのタイトル・止まった後 | 始める（練習が残っていれば練習から） | 練習なしで始める | メニューへ | 同上 | 学習モードへ |
| スコアゲームの練習 | 次のステップへ | 練習を全部飛ばして本番へ | メニューへ | 同上 | 学習モードへ |
| スコアゲームのプレイ中 | — | — | メニューへ（止める） | 同上（アームの復帰。かんたんモードの停止も戻す） | 学習モードへ |
| スコアゲームのリザルト | 次へ（演出を飛ばす → ランキング → 次のラウンド） | 同じ | メニューへ | 同上 | 学習モードへ |
| クレーンの画面（スタッフ用） | — | — | メニューへ | 同上 | 学習モードへ |

## 展示の一日の流れ（例）

1. 起動すると校正の画面。**F9** でアラーム解除 → まとめて準備（アームが動くので周りを確かめてから）
2. **F6** でメニューへ
3. **F10** で学習モードへ。読み込みや採点で止まったら **F6** で飛ばして続ける。**F7** で勉強を終えてゲームへ
4. スコアゲームの練習は **F7** で飛ばせる
5. プレイ中にアームがアラームで止まったら、周りを確かめてから **F9**
6. **F8** でいつでもメニューへ

## 安全

- **停止（Space / `stop`）はいつでも優先**する。復帰の途中でも、止めればまとめて準備は送られない（送られた後なら止め直す）。
- アームが動くのは **復帰** だけ。校正タブの「アラーム解除」「準備をまとめて実行」と同じコマンドを順に送るので、モーター・原点・モーションロック・`request_id` の関門はそのまま効く。復帰は 1 回押すだけで実行する（ユーザーの判断。周りを確かめてから押す）。
- 実機の状態が復帰を要らないとき（アラームなし・原点済み・モーター有効）は、復帰は何もしない。モーターがオフのとき（起動直後など）も復帰の対象で、まとめて準備がモーターを有効にする。
- 学習モードの「次へ」は、今までの F6 のスキップと同じ（読み込み・採点の失敗は「まちがい」にしない）。

## スタッフ用リモコン（M5StopWatch）

手元の M5StopWatch から、画面のボタンやキーボードを使わずに同じ操作ができる。リモコンは UFO-DeviceHub の機器（Device ID 0x30）で、ESP-NOW でハブへ送り、ハブ → バックエンド（`devicehub_event`）→ ゲームの順に届く。リモコンは押されたことを送るだけで、ゲームが `StaffControl.run()` で今の画面の意味に従って実行する。リモコン本体の画面・ボタン・設定は UFO-DeviceHub の `docs/hardware.md`「スタッフ用リモコン」。

| リモコン（青ボタンで画面を切り替え） | ゲームで起きること |
|---|---|
| スタッフ画面: つぎへ・とばす・メニュー・きりかえ（長押し）、黄ボタン = つぎへ | `next` / `skip` / `menu` / `switch`（F6 / F7 / F8 / F10 と同じ） |
| スタッフ画面: ふっき（**1.2 秒長押し**） | `recover`（F9。アームが動く） |
| ストップ（どちらの画面にもある） | `stop`（Space と同じ） |
| そうさ画面: 黄ボタンを押しながら傾ける | 手でつまんで動かすのと同じ（つまんだ位置 = 押した瞬間の傾きが中心。離すと止まる） |
| そうさ画面: じょうげ オン + 黄ボタン + 前後 | 手のひらを下にしてつまんだのと同じ（奥に倒す = アームを上げる。W と同じ向き） |
| そうさ画面: つかむ / はなす / ポータル（長押し） | 手の形 グー / ピース / 指 1 本を約 1.2 秒見せたのと同じ（通常モード: 爪を閉じる / 開く。かんたんモード: その場でキャッチ / ポータルへ運ぶ。練習のステップも同じ形で進む） |

例: メニューで「つぎへ」→ 選んでいるものを始める。学習モードで読み込み・採点の待ちは「つぎへ」で飛ばす。スコアゲームの練習の操作待ちは「つぎへ」で次のステップへ。ハイスコアの画面の後は「メニュー」でホームへ。アラームで止まったら周りを確かめて「ふっき」を長押し（アラーム解除 → まとめて準備）。

### 仕組みと安全

- `game/scripts/input/staff_remote.gd`（`StaffRemote`）が `devicehub_event` の `STAFF_ACTION` を操作名に、`REMOTE_INPUT` を手のイベント（`hand_control`）に変える。手のイベントは `GestureControl` にカメラの手と同じように入るので、ゲート（タイトル・学習モード・アラーム・自動キャッチ中・実機の条件 `gesture.allow_real_robot` など）、強制停止のラッチ、古いイベントでの停止はそのまま効く。
- リモコンのイベントが来ている間（最後のフレームから 0.6 秒）はカメラの手を使わない。カメラに戻るときは手の流れを新しくする（つまんだままの手は一度離すまで動かない）。
- リモコンは押している間 100 ms ごとに送り、離したら 1 回送って止まる。届かなくなったらゲームは 0.35 秒（`gesture.stale_ms`）で止める。フレームの番号が古いものは捨てる。
- 押し始めは 1 フレーム目を「手が見えた」、2 フレーム目を「中心でつまんだ」として扱う（最初からつまんでいる手は `GestureControl` が止める、つまんだ位置がスティックの中心になる、ため）。動き出しは押してから約 0.2 秒。
- ジェスチャー操作がオフ（H、`--no-gesture`）でも、リモコンの操作が来たらオンにする（人がリモコンで操作を始めたため）。
- 傾きの向きは、カメラの手の向きの設定（`gesture.joystick` の反転・入れ替え・上下反転）を打ち消して渡すので、右に傾ける = 画面の右（ロボットの +X）、奥 = +Y になる。

## 外部デバイス（これから）

ほかの外部デバイスを足すときも、新しい操作を作らず、この 6 つの名前を送る（`StaffControl.run(操作名, 送り元)`）。
