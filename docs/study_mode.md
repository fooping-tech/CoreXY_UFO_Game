# UFOくん 学習モード（#86）

子どもが宿題に取り組むのを、青い UFO の「UFOくん」が見守り、難問ではアームで近くまで見に行って解説し、
終わったらお祝いして片付けまで手伝う体験です。Godot のメイン画面で動きます（別アプリではありません）。

## 1. 体験の流れ

| 段階 | 画面と UFOくん | 中身 |
|---|---|---|
| 1. 勉強の時間 | 「そろそろ勉強の時間だよ！」「今日は月曜日！宿題をチェックしよう！」。背景は明るい暖色のドット絵（`StudyBackdrop`: 黄色から桃色の空、太陽、雲、星、算数の記号、丘と木の机。コードで描く）。下のジェスチャーの小さなカメラの映像は学習モードの間は出さない（手の認識は続く）。音楽 `study.mp3`（`study_mode.bgm.study`）が流れ始め、答え合わせ（採点）が始まると `study_check.mp3`（`study_mode.bgm.check`）に変わる。どちらも `game/assets/audio/bgm/`（各 PC のもの、Git に入らない）。音量はスコアゲームの BGM と同じ計算（-18 LUFS にそろえる `gain_db`）。真ん中にプリント（camera は AI に送る切り出しの映像）を大きく、右上に「宿題 n / m 問」・勉強時間・ゲームエネルギー ⚡ | `INTRO`。曜日は `study_mode.weekday_label` |
| 2. 宿題開始 | 「席について、プリントを置いてね！」。見つけるまでは、ドット絵の額縁（木の枠に点滅する電球）の中にカメラの映像全体を出し、置いてほしい範囲（プリントタブの「おく場所」。未設定なら「読む範囲」、#298）を点滅する点線・かぎ・矢印と「ここへおいてね！」で示す。虫眼鏡のドット絵がウロウロ探す（simulated は机の絵）→ 見つけたら巨大な「みつけた！」、シェイク・フラッシュ・クラッカー・周りからはじけるキラキラ、ドン＋ピコーン →「宿題スタート！」 | `WAITING_FOR_WORKSHEET` → `STUDYING`。学習タイマー開始。学年は設定画面の「最初の学年」（画面では選ばない、#283） |
| 3. HELP | Y キー: 実物のプリントでは、止まっていそうな問題（書きかけの最初、なければまだ書いていない最初）。全部書けている・まだ読めていないときは「どの問題かな？」と聞いて動かない（見本のプリントは `help.problem`）。俯瞰カメラに指で 1・2・3 本を見せる →「問題 N だね。教えてあげようか？」→ いいね（親指を立てる）で「わかった！問題 N だね。」「ぼくが近くで見てみるよ！」。Y キーは `study_mode.help.problem`（既定は問題 3） | `HELP_LOCATING` → `HELP_MOVING`。その問題を見に行く（#136） |
| 4. 撮影と解説 | 丸いスコープにアームのカメラ（動き出しから）。10cm で撮って、その写真をスコープに出したまま解説を吹き出しと声で。問題文はアームのカメラの写真から AI が読む | `CAPTURE_10CM` → `AI_EXPLAINING` → `RESUME_STUDY` |
| 5. 答え合わせ（#236・#237） | 「こたえあわせ！」と「ぜんぶ書けたね！UFOくんと答え合わせしよう！」。読み取りの間は画像の上をスキャンの光が走り「答案を確認中！」。プリントを 1 回読み、**読んだ画像を真ん中に大きく出して**、問題 1 から 1 問ずつ（1 問 2.5 秒）ドラムロール →（せいかい）その答えのらんに手書き風の赤い **○** が描かれ、巨大な「せいかい！」、画面シェイク・フラッシュ・キラキラ、ドーン＋パワーアップ音、⚡ +1、続けば「COMBO × n!!」／（見てみよう）黄色の点線の枠と **？**／（見えにくかった）小さな灰色の ？ | `ANSWER_CHECK_READY` → `SHEET_SCANNING` → `GRADING_QUESTION` |
| 6. 見直し | 見直す問題だけ、プリントのヒント（答えは言わない）。書きなおしたら R でもう一度読む（`RESCAN`。正解になった問題だけもう一度発表）／Enter でこのまま進む | `REVIEW_SUMMARY`（全問せいかいなら通らない） |
| 7. 報酬の発表 | UFOくん の下に MISSION COMPLETE!（全問せいかいは PERFECT!）と、1 行ずつ「3もん かくにん」「2もん せいかい 1もん みなおし」「TIME +20」「POWER TICKET ×1」。続けて、ドット絵の目覚まし時計の「TIME +20 GET!!」、次に金色のチケットの「POWER TICKET GET!!」（アイテムゲットの演出）。大きな画面シェイク、紙吹雪・クラッカー 2 回・フラッシュ・ジャックポットのジングル。「3もん かくにん 2もん せいかい 1もん みなおし」、TIME の数字がカチカチとカウントアップ、「POWER TICKET ×1」 | `REWARD_CALCULATING` → `REWARD_REVEAL`（1 回だけ） |
| 8. パワールーレット | ドット絵のアイテム（SPEED UP = 稲妻、DOUBLE SCORE = ×2 の金貨、MULTI BALL = 3 色のボール。`PowerItemArt`、16×16 ドットをコードで描く）の上を光がカチカチと回り、だんだん遅くなって 1 つに止まる（約 3 秒、偶然で決まる。子どもは選ばない）。止まったら **アイテムゲット**: 画面が暗くなり、回る光の筋の中でアイテムが大きくはずみ、「○○ GET!!」、シェイク・爆発。ゲームの準備の画面では手に入れたアイテムが浮かぶ | `POWERUP_SELECT`（チケットがあるとき） |
| 9. 片付け | 「最後にお片付けをするよ！」。今日のお勉強時間を大きく表示 | `CLEANUP`（失敗は `CLEANUP_FAILED`）。`study_mode.cleanup.enabled` が false なら通らない |
| 10. ゲームへ | STUDY POWER LOADED! /「TIME +20」「DOUBLE SCORE READY」/「ゲームで遊ぶ ▶ 5」（数字が減り、5 秒で自動的にスコアゲームのタイトル画面へ。押せばすぐ） | `GAME_READY_WITH_REWARD`。報酬を引き渡す（`last_reward`、イベント `study_reward`）。スコアゲームへの引き継ぎは #239 |

**声**: VOICEVOX が「UFO」を「ユーエフオー」と読むので、声に送る文だけ「ユーフォー」に置き換えます（吹き出しは「UFOくん」のまま）。

**音**: 場面ごとに、ゲームの効果音ファイル（`assets/audio/manifest.json`、Kenney・CC0）、効果音ラボの効果音（`assets/audio/se/`: 正解の発表とプリントを見つけたときに `don.mp3`・`pico.mp3`、報酬のファンファーレに `jan.mp3`。出典と規約は `se/README.md`。ないときは合成音で代わりに鳴らす）と合成音を重ねて鳴らします（`StudySounds.CUES`: 答え合わせの開始・ドラムロール・せいかい・COMBO・見てみよう・報酬・PERFECT・カウント・パワーの表示と決定・ゲームの準備）。

**答え合わせの決まり（`StudyGrading`）**: 読み取りはモデルの推定で、正しい答えを「まちがい」とすることがあります。そのため赤いバツは出さず、「まちがい」とも言いません。サーバが式を計算し直して確かめた `correct` だけを ○ にし、`incorrect` / `partial` は「見てみよう」、`unreadable` や見切れ・読み取れなかった問題・読み取りの失敗は「見えにくかった」（判定しない）にします。一度 ○ になった問題は、あとの読み取りで下がりません。報酬は問題ごとの結果から毎回計算し直すので、再スキャンで二重に付きません。

**報酬**: 正解 1 問で TIME +10 秒（`time_per_correct_s`、最大 +30 秒 `time_max_s`）、全問を確認し終えたらパワーチケット 1 枚。HELP を使っても減りません（`used_help` は記録だけ）。全問正解は PERFECT! の演出だけ（報酬は増えない）。設定は `study_mode.answer_check`。simulated では `demo_results`（既定: 1 せいかい・2 見てみよう・3 せいかい）で、R の再スキャンは見直しの問題を書きなおした扱いにします。camera（`study.ai: local`）では、答え合わせを始めたときに、映像が落ち着くのを待ってから（最大 6 秒、#298）、俯瞰カメラの画像全体をプリントタブの向きに回し、「読む範囲」を `roi` として付けて `/v1/sheet` で 1 回読みます（バックエンドの `sheet_read`。サーバが範囲を切り出す。送り方は `docs/ufo_api_spec.md` の 6.1.1）。○ を描く画像は、その範囲を切り出したもの（画面の左の「カメラ（AI に送る画像）」と同じ）。読めなかったときは見守りが最後に読んだ結果を使い、それもなければ全部「見えにくかった」にします。プリントを見つけてすぐ答え合わせに入るとき（#281 `check_on_found`）は、見つけたときの見守りの読み取り（同じ `/v1/sheet`、同じ範囲）をそのまま採点に使い、2 回目は読みません（#306。○ はその読み取りで送った画像に描く）。次のときだけ読み直します: R の再スキャン、宿題の途中から答え合わせに入るとき、そのあと画像が変わった（プリントが動いた・手がかかった）、別の画像を送り中、見守りの結果が 60 秒より古い、○ の位置（`answer_box` / `box`）がない。

**問題の数は固定ではありません**（#237）。camera（local）では、見守りで読み取れた問題の番号（例: 3・4・5 番、5 問など）を問題にし、一度見えた番号は手で隠れても減らしません。全部の番号が「かけた」になったら答え合わせを始めます。答え合わせで初めて読めた番号も採点に加えます。右の問題のチップは問題の数だけ出ます（4 つずつ折り返し）。**camera（local）のプリントは本物のプリントで、見本のプリント（`config/worksheets.json`）ではありません**（#287）。番号が同じでも見本の問題文・ヒント・答えは使いません: 見直しの声は「Nばんは、もういちど 問題を ゆっくり 読んでみよう」、AI の解説が使えないときはどの問題にも合うヒント（`StudyServices.ANY_PROBLEM_HINTS`）、解説の要求に `worksheet_id` を付けない（見本の問題文と比べない）、問題の場所探しも番号だけ、近接の丸い表示に問題文を書かない、手で選べるのは読み取れた番号だけ。声の会話で学習支援 AI に「言ってはいけない答え」として渡すのは、プリント読み取りが返した本物の正しい答え（`correct_answer`。バックエンドだけが持ち、ゲームには渡さない）です。学年は設定の「最初の学年」を送ります（AI のヒントは #238）。simulated と cloud（見本のプリントを印刷して使う）では見本のプリント（3 問）を使います。

止めたとき（Space）やアームの異常は `ERROR`（Enter で宿題に戻る。勝手に動き直さない）。

### プリントを見つけたらすぐ答え合わせ・対話モード（#281）

- プリントを見つけたら、宿題の時間（STUDYING）を通らずに、すぐ答え合わせ（ANSWER_CHECK_READY → 読み取り → 1 問ずつ）に進む（`study_mode.check_on_found`）。
- 声の対話（V キー・マイクのボタン）は**対話モードのときだけ**。いいね 👍 を 3 秒（`study_mode.dialog.thumb_s`）続けると対話モードに入る。受け付けるのは、プリントを見つける前（待っている間）と、答え合わせの結果のまとめ（見直し: REVIEW_SUMMARY）のとき。採点の途中・報酬の演出中は受け付けない。
- 見つける前に対話モードに入ったときは今までどおり: 宿題の時間（話しながら解く、HELP）→ 書けたら答え合わせ。
- `study_mode.dialog.needs_thumb: false` で以前の動き（いつでも話せる）。実機（カメラの手のいいね、声）は未検証。

## 2. 起動と操作

```bash
./start.sh --mock --no-gesture --study-mode       # バックエンド --mock + ゲーム（学習モードで開始）
./start.sh --game-only --study-mode               # ゲームだけ（Godot 内蔵の Mock でアームを再現）
./start.sh --game-only -- --study-demo simulated  # simulated / camera を指定して開始
./start.sh --study-mode                           # 実機 + ジェスチャー（demo.source が camera のときだけアームを動かす）
```

起動時のタイトル画面で「学習モード」を選ぶか、ゲームの中ではいつでも **F5** で学習モードの開始・終了。

| キー | 働き |
|---|---|
| Enter | 次へ・大人の確認（プリントを置いた / 全問書けたことの確認 / ジグをつかめた / 片付け失敗の確認 / ゲームで遊ぶ） |
| 指 1・2・3 本 → いいね | その問題の HELP（#136。`study_mode.hand_help`: 指の形を `hold_ms` 見せると申し出、`offer_s` 以内のいいねで開始。ハンドトラッキングが要る） |
| Y | HELP（`study_mode.help.key` / `help.problem`。宿題アシスタントの「止まっている問題」キーと同じ） |
| Space | 止める（ゲームの停止キー。学習モードの動きも止める） |
| 1 / 2 / 3 | 模擬デモ: その問題に記入した（記入中 → 次の読み取りで記入済み） |
| F6 / F7 / F8 / F9 / F10 | スタッフ操作（#260、`docs/staff_operations.md`）: 状態のスキップ（読み込み・採点を飛ばして続ける）/ 勉強を終えてゲームへ / メニューへ / 復帰 / ゲームへ |
| Shift+F7 / Shift+F8 | 開発用: 失敗の注入（位置特定・アーム停止・AI・音声・手で隠れる・片付けを順に） / 最初から |
| Esc | タイトル画面に戻る（学習モードを止める） |

学習モード中は F1 のデバッグパネルを閉じて始めます（F1 で再表示）。ゲームの他のキーはそのまま。
HELP と片付けの間は、矢印・W/S による手動操作を受け付けません。学習モードの間、手はアームや爪を動かさない（指の数といいねは HELP に使う）。

## 3. 何を使うか（`study_mode.demo.source`）と、どのロボットか（start.sh）

config で決めるのは「模擬か、カメラと AI を使うか」だけです。**アームは start.sh がつないだロボット**に従います（`./start.sh` = 実機、`--mock` = バックエンドの仮想クレーン、`--game-only` = ゲーム内蔵の Mock）。

| `demo.source` | プリント・記入 | 位置 | 解説 | 外部への送信 |
|---|---|---|---|---|
| `simulated`（既定） | 模擬（`worksheet_wait_s` 秒で発見。記入は 1/2/3 キー、`auto_answer` で 1・2 問を自動） | プリントデータから | プリントのヒント | **なし** |
| `camera`（`study.ai: local`、既定） | 俯瞰カメラ + プリント読み取り（`/v1/sheet`） | プリント読み取りの枠 + camera_map | 学習支援 AI | 俯瞰と近接の画像を**学習支援 AI のサーバ（同じ LAN）だけ**へ。クラウドへは送らない |
| `camera`（`study.ai: cloud`） | 俯瞰カメラ + Jev（HomeworkClient の見守りにワークシートを付ける） | Claude/Codex + Jev + 基準マーク + camera_map | Claude / Codex（`explain_provider`） | 俯瞰と近接の画像を Jev（Cloudflare）と Claude / Codex へ |

| つないだロボット | `simulated` | `camera` |
|---|---|---|
| ゲーム内蔵の Mock（`--game-only`） | 動く | 動かさない（バックエンドが要る） |
| バックエンドの仮想クレーン（`--mock`） | 動く | 動く |
| 実機（`./start.sh`） | **動かさない**（模擬の位置はプリントのデータで、机の上の本物の位置ではないため） | 動く。ただし高さ校正と確認がないとバックエンドが拒否する |

前の `study_mode.demo.mode`（`mock` / `camera` / `real`）と `--study-demo mock|real` も読めます（`mock` = `simulated`、`camera` / `real` = `camera`）。

声は `homework.speech`（VOICEVOX → macOS `say`）。バックエンドがないとき・声が作れないときは文字だけで進みます（行ごとの読み時間で次へ）。

## 4. 設計

- **体験と機械を分ける。** `StudyModeController`（Godot）は体験の状態機械だけ。`RobotState` を書かず、ロボットへのコマンドも自分では送りません。動きは `StudyServices` に頼み、`StudyServices` はバックエンドの**シーケンス 1 本**（モーションロックを持つ）を始めるか、ゲーム内蔵の Mock に目標を渡すだけです。JOG は送りません。
- **バックエンドの動き。**
  - HELP: 既存の `ApproachSequencer` に段階撮影を追加。`homework_approach {xy|u,v, stages: "study"}` で、ひとつのモーションロックのまま RAISE → MOVE_XY → (LOWER → SETTLE → HOLD) × 3 → RAISE_BACK → RETURN_XY。各 HOLD はゲームの撮影後 `homework_approach_release {stage}` で次へ（別の段の release は無視）。
  - 片付け: `sequence/cleanup.py` の `CleanupSequencer`（同じ安全の枠）。`study_cleanup_start` / `study_cleanup_confirm` / `study_cleanup_status`。
  - STOP / soft_stop / モーター OFF / 操作者の切断で FAULT（ロボットの stop = ABORT）。再接続しても自動では再開しません。
- **認識と AI（既存の再利用）。**
  - 進捗: `HomeworkService` の Jev 呼び出しに、問題ごとの「解答欄に手書きの答えがあるか」の質問を 3 つ追加（同じ 1 回の呼び出し）。`homework_progress.questions`。
  - 判定（ゲーム側 `StudyQuestionTracker`）: 未着手 / 記入中 / 記入済み / 判定保留。記入済みは 2 回続けて（`confirm_readings`）、完了は全問が `complete_readings` 回続けて記入済みのときか、大人の Enter。手で隠れているときは更新しません。**正解かどうかは判定しません。**
  - 位置: `homework_locate {kind: "problem", problem: 3, worksheet_id}`。Claude/Codex が解答欄を答え、Jev が同じ解答欄を探し（一致しないと動かさない）、さらに Jev が見つけた四隅の基準マークからページの位置を計算して、問題 3 の領域と合わないときも動かしません。動く先は camera_map（ホモグラフィ校正）で XY に変換し、校正が使えないとバックエンドが拒否します。
  - 解説: `homework_explain` で俯瞰 + 3 枚の近接画像を 1 回の質問で渡し、構造化 JSON（`problem_number, recognized_problem, confidence, hint, explanation, speech_text, needs_confirmation`）を受け取ります。プリントデータの問題文と照合し、違えば `needs_confirmation`。失敗時はプリントのヒントで解説します（`fallback`）。
  - 学習支援 AI（#104、§8）: `study.explain_provider: "tutor"` のとき、解説だけを学習支援 AI（UFOくん API）に頼みます。問題が写っていなければ、もう一度見に行きます（最大 2 回）。
- **演出。** GameState のイベント `study_*` を `vfx_director.gd` が受けて既存の PixelFX（`success_confetti`、`success_sparkle`、`start_energy`、`grab_burst`、`fail_poof`）を出します。クラッカー・フラッシュ・バナーは HUD（`ui/study_hud.gd`）。効果音は `study_mode/study_sounds.gd` がその場で合成（音声ファイルなし）。

| ファイル | 役割 |
|---|---|
| `game/scripts/study_mode/study_mode_controller.gd` | 体験の状態機械、キー、大人の確認 |
| `game/scripts/study_mode/study_services.gd` | モードごとの外部（Mock / Jev / AI / ロボット）との窓口 |
| `game/scripts/study_mode/question_tracker.gd` | 問題ごとの状態と完了の判定 |
| `game/scripts/study_mode/study_speech.gd`, `study_sounds.gd` | 吹き出しと声の同期、効果音 |
| `game/scripts/study_mode/worksheet_catalog.gd` | プリントデータ（Godot） |
| `game/scripts/ui/study_hud.gd` ほか `study_*_view.gd`, `study_crackers.gd` | 画面 |
| `backend/.../study_mode/` | プリントデータ（Python）、高さ校正、解説 |
| `backend/.../homework/questions.py` | 問題ごとの Jev 質問 |
| `backend/.../sequence/cleanup.py` | 片付けシーケンス |
| `tools/build_worksheets.py` → `config/worksheets.json`, `docs/worksheets/` | プリント（12 学年 × 3 問）と印刷用 A4 SVG |

## 5. プリント

## 7. 安全

- 実機では、HELP と片付けのアームを動かす前に**大人の Enter** が必要です（Mock の準備＝モーター ON・原点復帰も Enter）。

- ジグの把持は自動で判定しません（センサーがない）。大人が Enter で確認し、`grip_confirm_timeout_s` で FAULT。

## 8. 学習支援 AI（UFOくん API、#104）

### 学習モードの AI はローカルだけ（#232、`study.ai`）

`study.ai: "local"`（既定。設定画面の「学習モードの AI」）では、学習モードは学習支援 AI のサーバ（ローカル LLM、`study.tutor_url`）だけを使います。Jev・Claude Code・Codex は呼ばず、Jev のキーも要りません。`"cloud"` にすると、前の動き（Jev + Claude / Codex）に戻ります。

| 用途 | 中身 |
|---|---|
| 進み具合 | 俯瞰カメラの画像を `/v1/sheet` で読む（1 回 約 10 秒。読んでいる間の画像は捨てる）。正解・まちがい = 記入済み（0.95）、書きかけ = 0.5、空白 = 0.05、読めない・見切れ = 判定しない。全部読めないときは表示を保つ（`held`）。正しいかどうかはゲームに渡さない（`answers` は状態と読み取った答えだけ） |
| 問題の場所 | `/v1/sheet` の答えのらん（なければ問題の枠）の中心。**stream で 1 問ずつ受け取り、目的の問題が届いたら接続を閉じる**（全部読むのを待たない）。見つからない・枠がプリント全体ほど大きいときは動かさない。その先は今までどおり camera_map で XY |
| 解説 | 学習支援 AI（`explain_provider` は使わない） |

俯瞰カメラの画像は、設定画面の「プリント」タブで俯瞰カメラに決めた**向きと範囲**で切り出して正立させてから送ります（`SheetFrame`、`user://sheet_check.cfg`）。学習モードの画面の左のプリントも、このとき**送るのと同じ切り出した映像**（0.5 秒ごと、「カメラ（AI に送る画像）」）になります（プリントの絵ではなく）。`/v1/sheet` は同時に 2 件まで送ります（見守りの読み取り中でも、場所探しを待たせない）。場所の答えは、ゲームが元の画像の座標に戻してから camera_map に渡します。アームのカメラの近接画像は回しません（先端カメラの校正と `navigate` のずれが元の向きのため）。

認証が 3 回続けて断られると（トークン・許可 IP・設定）、見守りは自分で止まります。読めないとき・つながらないときも学習モードは止まらず、解説はプリントのヒントになります。

解説を、別の PC（Windows・RTX）で動く学習支援 AI に頼めます。答えを教えずに段階的なヒントを出し、目的の問題が写っていなければ、どちらにどれだけずれているかを返します。引き継ぎ資料と見本のコードは学習支援 AI 側の `integrations/corexy_ufo/`（`HANDOFF.md`、`PATCHES.md`）。

### つなぎ方

1. 学習支援 AI の PC で `uv run python server/tutor_app.py`（起動時に `https://<IP>:8444/` と許可する接続元を表示）。
2. この Mac に置く（**Git にもチャットにも出さない**。`config/secrets/` は Git に入らない）:
   - `config/secrets/tutor_token.txt`: トークン（1 行）。**サーバがトークンなしで動いているときは置かない**（ファイルがなければ Authorization を付けずに送る、#128。サーバがトークンを求めると、校正タブの「AI・外部サービス」と接続テストがそう言う）
   - `config/secrets/tutor_cert.pem`: サーバの自己署名証明書（公開してよい方。`key.pem` は受け取らない）。この証明書だけを信頼し、IP で接続するのでホスト名は照合しない（検証そのものは切らない）
3. 設定画面（歯車 → 設定 → Study タブ）で「学習モードの解説」を「学習支援 AI」、「学習支援 AI の URL」を `https://192.168.x.x:8444` にして保存し、`./start.sh` で起動し直す（`config/local_settings.json` の `study.explain_provider` / `study.tutor_url`）。
4. 接続テスト: `python3 tools/check_tutor_api.py`（URL・トークン・証明書は config から。TCP → TLS → 許可 IP → トークン → 推論 3 種の順に確かめ、だめなところで直し方を出す）。

`study.provider`（Claude Code / Codex）は今までどおり、アドバイス・問題の位置の判定（#79）・Study タブに使います。学習支援 AI のアダプタは解説の文（「子どもは問題 N で困っています」）しか読めないので、`provider` を `tutor` にはしません。

### 何を送るか

- 10cm の近接画像 1 枚と「N ばんが わからない」、学年（`tutor_grade`、プリントの学年が読めればそれ）。俯瞰・5cm・いちばん近くの画像は送りません。サーバは画像をディスクに保存しません。
- 子どものプリントには名前などが写ることがあります。実際の子どものプリントで評価データを集めるときは、保護者の同意と個人情報の除去が必要です。

### 声で家庭教師 AI と話す（#233）

宿題中（`STUDYING` / `RESUME_STUDY`、カメラのとき、`study.ai: local`）、子どもは **V キーを押している間**（または UFOくんの吹き出しの上の 🎤 ボタンを押している間）話しかけられます。離すと次の順に進みます。

1. バックエンドが録音を止め、この Mac の **mlx-whisper**（`study_mode.voice.model`、既定 `mlx-community/whisper-large-v3-turbo`）で文字にする。2 回目からは 1 秒ほど。最初の 1 回だけモデル（約 1.6GB）をダウンロードし、バックエンドの起動時に読み込んでおく（`preload`）
2. 子どもの言葉を吹き出しの上に出す（「きみ:「3ばんが わからない」」）
3. 言葉・俯瞰カメラの画像（プリントタブの向きと範囲で整えたもの）・話題の問題・それまでのやりとり（`messages` の user / assistant）を、学習支援 AI の会話 API へ **`format: "dialog"` の stream** で送る（[ufo_api_spec.md](ufo_api_spec.md) §5.2・§5.4）。子どもが番号を言えば（「3ばん」「さんばん」「③」など）その問題、言わなければ話題の問題を `target_problem` にする
4. 返事は **1 文できるたびに** UFOくん が言い始める（最初の 1 文まで 約 0.5 秒、全体で 約 1 秒）。残りは順に続く。別の番号を言うと、その問題のやりとりを新しく始める
   - stream の文はサーバの確認の前なので、答えを言っていそうな文（「こたえは 5」、プリントのデータの正答を「= 85」「85 だよ」の形で言う文）は言わず、そこから先はサーバが確かめた文だけを言う
   - 最後にサーバが確かめた文と比べ、まだ言っていない部分（`rest`）だけを言う。もう言った文は言い直さない
   - 学習支援 AI のモデルは、しばらく使わないとサーバが外す（次の 1 回が 約 10 秒）。学習モードのセッションの間は、始めたときと、会話のない 4 分ごと（`warm_every_s`）に、灰色の小さな画像で短い会話を 1 回送って温めておく
5. 返事が「近くで見たい」（`need_recapture`）なら、その問題の HELP（アームのカメラで見に行く → 解説）を始める。実機では今までどおり大人の確認が要る
6. **問題の番号を言ったとき**（「1ばんが わからない」「３番」「(2)」「④」「にばん」「三番」「もんだい 5」）は、会話ではなく、その問題を**見に行く**（HELP: 俯瞰カメラの画像で場所を探し、画面の画像の上にその問題を点滅する枠と「1ばん ここ！」で示す → アームのカメラで近くを撮る → 学習支援 AI が解説）。実機では大人の Enter が要る

| 決まり | 中身 |
|---|---|
| 録音 | 押している間だけ、最長 `max_s`（20 秒）。UFOくん が話している間は聞かない。Space で取り消し。ゲームとの接続が切れたら録音を捨てる |
| 音声の扱い | メモリの中だけ。ファイルに残さない、ネットにもサーバにも送らない。サーバへ送るのは文字だけ |
| 聞き取れないとき | 短すぎる（0.4 秒未満）・小さすぎる・Whisper が無音で作る決まり文句（「ご視聴ありがとうございました」など）は「よく きこえなかった」と言う。小さすぎるかは、録音の中でいちばん大きい 0.25 秒の音量で決める（`study_mode.voice.min_rms`、既定 0.003。#246: 録音全体の平均だと、話す前後の無音で少し離れた子どもの声が 0.004 を下回り、文字にならなかった）。1 回ごとに長さと音量（いちばん大きい部分・全体）をログに出す（`voice: 2.1 s, loudest 0.0051, whole 0.0024 -> Whisper`） |
| つながらないとき | 「いまは うまく こたえられないみたい」と言って宿題を続ける（止まらない） |
| マイク | 既定の入力（`device` で名前の一部を指定できる）。初回に macOS がマイクの許可を求める（`./start.sh` を動かすターミナル。VS Code のターミナルなら VS Code）。5 秒で開けなければ、許可の場所を言って断る。バックエンドの動き（ロボットのコマンド）は止めない |

設定は `study_mode.voice`（`enabled`、`key`、`max_s`、`model`、`language`、`device`、`preload`）。バックエンドとのやりとりは `homework_listen_start` / `homework_listen_stop`（→ `homework_heard`）/ `homework_listen_cancel` / `homework_talk`（→ `homework_talk_result`）。hello の `study_voice` が false のときは、理由（`study_voice_problem`）を画面の小さな文字で出す。

### プリント 1 枚の読み取り（POST /v1/sheet、#230）

同じサーバに、プリントの写真 1 枚から、問題ごとの枠・答えのらんの枠・答えの状態（正解 / まちがい / 空白 / 書きかけ / 読めない）・読み取った答えを返す API があります（1 枚 約 10 秒）。学習モード（`study.ai: local`）では、見守りと問題の場所探し（#232）、答え合わせ（#237）に使っています。

- クライアント: `backend/src/corexy_ufo_backend/study/sheet_client.py`（`make_sheet_client(StudyConfig)` で作る）。URL・トークン・証明書は上の `study.tutor_*` と同じです。証明書は解説と同じく `tutor_cert.pem` だけを信頼し、ホスト名（IP）は照合しません（#285。前は照合していたので、サーバの IP が変わると解説はつながるのにプリントだけ読めず、「ここへおいてね！」から進まなかった）。待ち時間は `study.sheet_timeout_s`（既定 180 秒、120 秒より短くはしない）。
- 送る前に、EXIF の回転を画素に反映し、長辺 1800 画素・4MB 以下の JPEG にします。返る `box` は送った画像の幅と高さを 1000 とした値です。`SheetResult.boxes_on_source()` を使うと、元の写真のピクセルで受け取れます。
- 同じサーバへは 1 件ずつ送ります。401 になったトークンは、直すまでもう送りません（10 回まちがえるとサーバが 10 分ブロックするため）。429 は 10 分待ちます。500 は 1 回だけ、503 は 5・10・20 秒あけて送り直します。400・403・413 は送り直しません。
- `problems` が空のときは「読めなかった」として扱います。結果はモデルの推定なので、人が確かめられる見せ方にしてください。
- 校正タブの「AI に試しに質問」を押すと、見本のプリント（`tools/samples/worksheet_sample.jpg`）も `/v1/sheet` で読み、「プリント読み取り（/v1/sheet）」の行に結果を出します。`/v1/sheet` だけを確かめる専用のパスはサーバにないので、開いたときの自動の確認では送りません。そのかわり自動の確認でも、「学習支援 AI」の行は `study.ai: local` のとき、プリント読み取りのクライアント（同じ TLS・トークン）でも `/api/health` と `/v1/models` を確かめ、つながらなければ「解説はつながるが、プリントの読み取りがつながらない」と ✗ で理由を出します（#285）。
- 学習モードのプリント待ち（「ここへおいてね！」）で読み取りが失敗していると、映像の下に赤い枠で「プリントを よみとれないよ（大人の人へ）」と理由（証明書・接続できない など）を出します。1 枚読めたら消えます（#285。camera のときだけ）。
- つないだカメラで試すとき: F1（または歯車）→ 設定画面の「プリント」タブ。俯瞰カメラかアームのカメラを選ぶ。**送る前に整える**: 「送る範囲をドラッグで決める」を押してライブ映像の上でプリントの部分を囲み、「向き」でプリントが正立するように回す（そのまま / 180° / 右 90° / 左 90°。カメラの向きで逆さに写るとき）。範囲と向きはカメラごとに `user://sheet_check.cfg` に覚える。「送る画像を見る」で送らずに確かめられる。「撮って読む」で送ると、**送った画像そのもの**の上に問題の枠（色は答えの状態）・答えのらん（細い枠）・サーバが切り出した紙（点線）が重なり、下に問題ごとの結果と、**サーバの返事（JSON。コピーできる）**が出る。「撮った画像」で範囲を描いた元の画像、「ライブ」でカメラの映像にもどる。画像はバックエンドの `sheet_read` を通って送られる（実機は動かさない。画像はどこにも保存しない）。
- 手で試すとき: `cd backend && uv run python ../tools/read_sheet.py <写真>`。結果を表示し、元の写真に枠を描いた `<写真>.sheet.jpg` を保存します。このファイルには児童の手書きが写るので、Git には入りません（`.gitignore`）。共有もしないでください。

### つながらないとき

ゲームも学習モードも止まらず、アームも動かさず、プリントのヒントで解説します（今までの `fallback`）。2 回続けて失敗すると（`tutor_fail_limit`）、`tutor_cooldown_s`（120 秒）は呼ばずにすぐプリントのヒントにします。URL がないとき・サーバがトークンを求めているのに置いていないときも同じです。

### HELP の場所探しの待ち時間（#244）

HELP の「問題 ◯ はプリントのどこ？」（`/v1/sheet` の stream）は、**20 秒**（`homework.locate_timeout_s`）であきらめます。サーバの同時実行の枠（2 件）が見守りの読み取りでふさがっているときの順番待ちも含めます。あきらめると UFOくん が「AI が いま こんでいるみたい」と言い、プリントのヒントを出します（アームは動かさない）。見守りの定期の読み取りと答え合わせの読み取りの待ち時間は今までどおりです。読み取りごとに、かかった時間と枠の順番待ちの時間をログに出します（`sheet: locate 3 answered in 4.2 s (1.0 s waiting for a slot)`）。

### 写っていない問題を探しに行く

1. 学習支援 AI が `navigate {kind: "move", offset}`（画像の中心から目的の問題までのずれ。画像の幅・高さを 1000）を返す。または `game.camera_move {direction: up/down/left/right, distance_mm}`（画像の上下左右に何 mm 動かすか。#242）。
2. アダプタが先端カメラの校正（`config/calibration.json` の `focus_camera`）で mm に直す（`d_mm`）。`camera_move` は、校正から「画像の右」がアームのどちら向きかを求め、`distance_mm` だけ動かす。`winch_up` / `winch_down` は言葉だけ。**校正がなければ `d_mm` を付けない = アームは動かない。** このときサーバの「さがしに いくね」は言わず、子どもにできることを言う（「◯ばんが ユーフォーの 下に くるように、プリントを ずらして くれるかな？」。`stay_words`）。画面の注意書きに「アームは動かしません: 先端カメラの校正がまだ」と出る。
3. ゲームは「あれっ、ここじゃないみたい。さがしに いくね！ 手を はなして まっててね。」と言い、**アームが前の撮影から戻り終わってから** `homework_navigate {u, v, camera, d_mm}` を送る。バックエンドは、前の撮影位置 + `d_mm` を全体カメラの u, v に直して返すだけ（**動かさない**）。1 回 60 mm を超える・3 mm 未満・可動範囲の外・全体カメラの校正が信用できる範囲の外は断る。実機では mm の目標は使わない。
4. いつもの段階撮影（`homework_approach`）をもう一度。実機では毎回、大人の Enter が要る（HELP と同じ）。
5. 最大 2 回（`MAX_NAV`）。見つからなければプリントのヒント。Space で止めると、もう探しに行かない。

`uncover`（手で隠れている）・`zoom_out` もアームは動かさず、「手や ものに かくれているみたい。どけて くれるかな？」「プリントを まっすぐ おいて、もう いちど おしえてね」と言います。

### 先端カメラの校正（実機・高さごとに 1 回。未実施）

**設定画面（F1）の「校正」タブ → 7「先端カメラの校正（問題を見に行く）」でできます（#242）。**

1. 2 の Z の上下と原点復帰、6 の撮影の高さを済ませる。
2. 文字の書いてあるプリントをステージに置く。6 の「10cm へ動かす（試す）」でアームを撮影の高さへ下ろし、矢印キーでプリントの真上へ（先端カメラに文字が写る所。動ける範囲の端から 10 mm 以上はなす）。
3. 「先端カメラを校正する」を押す。ゲームが先端カメラの画像を撮り、`move_xy` で +X・+Y・−X・−Y に 10 mm ずつ動かして撮る（4 枚）。先端カメラはロープに吊られた爪について揺れるので、基準の 1 枚目も含めて、**画像が止まってから**撮る（0.2 秒ごとの小さな画像の差が 2 未満で 5 回続く。止まって 1 秒以上）。4 秒たっても揺れていれば（実機の爪は 20 秒以上揺れていた）、0.5 秒おきに 6 枚続けて撮り、バックエンドがずれの中央値をとる（揺れは止まる位置の両側に振れるので）。画像は長い辺 400 px。位置ごとに「still / burst」と画像の動きをデバッグログに出す。もとの位置に戻ったら、5 枚をバックエンドに送る（`focus_calibrate`）。
4. バックエンドが位相限定相関で画像のずれを測り、`s = −A·d` の A を求めて `config/calibration.json` の `focus_camera` に保存する（`tools/calibrate_focus.py` と同じ形）。画像がほとんど動かない（1 mm あたり 0.3 px 未満）・ずれがばらつく（誤差 6 px 超え。紙が動いた）ときは保存しない。爪など先端カメラと一緒に動く物は画像の中で止まって見えるので、ずれ 4 px 以内の一致は数えない。断ったときは、測ったずれ（例: `(+10,+0)mm→(+0,-60)px`）を校正のカードに出す。アームが 6 の撮影の高さ（Z ±2）にないときは始めない。
5. 「1 mm あたり ○ px、誤差 ○ px」が出る。Space・動きの拒否・アラーム・タブを閉じる・接続切れで止まる（アームは Space で止まった所にいる）。

アームを動かすのは `move_xy` だけで、ソフトリミット・モーター・原点復帰の確認はほかの動きと同じです。校正の計算（`focus_calibrate`）と状態の問い合わせ（`focus_status`）はアームを動かしません。

手で撮った画像からも作れます（今までの方法）: 10cm の高さで先端カメラの画像を保存（`base.jpg`）→ 同じ高さのまま X に +10 mm 動かして `x10.jpg` → 戻して Y に +10 mm 動かして `y10.jpg`（紙や手を動かさない）。

```bash
cd backend && uv run python ../tools/calibrate_focus.py --height 10cm --base base.jpg --move x10.jpg 10 0 --move y10.jpg 0 10
```

`config/calibration.json` の `focus_camera` に保存されます。誤差（`residual_px`）が数 px 以内で、「1 mm あたり ○ px」がカメラの高さから見て妥当かを確かめます。
