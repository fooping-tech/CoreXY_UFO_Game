## 3. 既知の課題・今後

- 移動中の XY は推定（線形 smoothstep）。実機の実際の加減速プロファイルと合わないと、停止タイミングで UFO の揺れが実物と少しずれる。ファームウェアが移動中に位置を返せるようになれば `measured` に置き換わる。
- `ABORT` はアラーム + HOMED 解除のため、E-STOP 後は毎回 `clear_alarm` → `home` が必要（ファームウェア仕様）。
- Z は電源投入からの相対値。`z_zero` を忘れると `move_z` は NACK になる（意図的）。
- デバッグパネル表示中は描画領域が狭くなる。大きく揺らすとパネルの下に入ることがある（F1 で非表示にすれば発生しない）。
- Phase 4（サウンド、パーティクル強化、UFO の個性づけ）は未着手。成功/失敗演出はスプライトアニメ + 簡易パーティクルのみ。

## 追記 2: 動作中のチャタリング（2026-10-24）

ウィンドウ表示で実際に動かし、`--log-motion` で物理 tick と描画フレームをすべて記録して調査。Mock / Python バックエンドの Mock で確認済み・**実機未検証**。

| 原因 | 症状（ログの数値） | 修正 |
|---|---|---|
| 描画（約 110 FPS）で物理（60 Hz）の値を差分していた | 表情が 9 秒で 398 回切り替わる（`move_right` ↔ `normal`）、画面速度が 961 フレーム中 878 回 0/非 0 を往復、UFO が止まって見えるフレーム 443/961、`panic` の誤発火 | 手がかりを物理 tick で計算、描画は 2 tick 間を補間。切り替わり 22〜33 回、止まって見えるフレーム 0 |
| MockRobot（GDScript・Python とも）が目標の周りで振動し続けた | 停止後の位置が ±0.12 mm で振れ続け、状態が MOVING のまま | 離散時間の停止速度に修正。目標でぴたりと止まり IDLE に戻る |
| 30 Hz のサンプルを直線補間・遅延が短すぎた | 加速度が 0/2 倍で脈打つ、送信の揺らぎで再生が追いつき止まって跳ぶ | 単調 3 次補間、受信間隔に応じた遅延、送り手時計の平均推定、滑らかな停止 |
| バックエンドの送信ループが「処理 + 33 ms 待ち」だった | 実測 27 Hz、間隔が不揃い | 固定周期（30 Hz）、遅れたときはまとめ送りしない |

結果（xy_diagonal、Mock）: アンカー加速度の最大 約 100,000 → 150 cm/s²（Mock の設定 133 cm/s²）。WebSocket 経路ではこの環境でバックエンドが 150〜300 ms 止まることがあり、その瞬間にだけ小さな引っかかりが残る（データが届かない区間のため）。
