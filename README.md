# CoreXY UFO Game

実物の CoreXY 方式 UFO キャッチャー（M5Stack Core2 ファームウェア: `CoreXY_UFO`）と連動する、macOS 向け 2D ピクセルアートゲームです。
画面上端から垂れ下がるロープの先に青い UFO がつながっていて、現実のクレーンの XYZ の動きに合わせて 3D 物理シミュレーションで揺れます。

```
CoreXY_UFO_Game/
├── game/        Godot 4 プロジェクト（ゲーム画面・ロープ物理・UFO・デバッグUI・MockRobot）
├── backend/     Python 3.12+ / uv（USBシリアル・WebSocket・カメラ認識）
├── config/      game_config.json（Godot と Python で共有）
├── assets/      元画像とスプライトシート（Codex 製作、game/assets にコピー済み）
├── tools/       スプライトシート生成スクリプト
└── docs/        firmware_protocol.md（実機通信仕様）, test_report.md（検証結果）
```

## 必要なもの（macOS / Apple Silicon）

- Godot 4.4 以上（検証: 4.7.2）: `brew install --cask godot`
- uv: `brew install uv`（Python 3.12+ は uv が自動取得）
- 実機接続時のみ: M5Stack Core2 + USB ケーブル（CP210x/CH9102 ドライバ）

## Phase 1: 実機なしでゲームを起動する

```bash
cd CoreXY_UFO_Game/game
/Applications/Godot.app/Contents/MacOS/Godot --path .
```

または Godot エディタで `game/project.godot` を開いて ▶ を押します。
起動時は **MockRobot**（仮想クレーン）に接続された状態で、右側にデバッグパネルが出ます。

操作:

| キー | 動作 |
|---|---|
| ← → | X 移動（左右）。実機接続中は押している間だけ動く（JOG、40 mm/s） |
| ↑ ↓ | Y 移動（奥 / 手前）。実機接続中は同上 |
| W / S | Z（アーム上昇 / 下降 → 画面の UFO は下降 / 上昇）。実機接続中は押している間だけ動く（原点復帰前でも可）。最初に W でアームを一番上まで上げて、デバッグパネルの「ここを巻き上げ点（上）に」を押す（一番下まで下げて「ここを下げ点（下）に」も押すと、Z の換算を実測する） |
| Space | 停止（Mock は即停止。実機接続中は減速停止 `STOP`、アラームにならない） |
| V | スコープ（望遠鏡ビュー）を手動で開閉 |
| H | ハンドジェスチャー操作の ON / OFF |
| [ / ] | 爪（Z の先の 2 つ目のサーボ）を、設定したステップ（既定 5°）だけ回す |
| Q / A | 爪を記録した開き位置へ開く / 閉じ位置へ閉じる（両方を記録してから。下の「爪のテスト」） |
| G / F | 成功 / 失敗演出 |
| F1 / Tab | デバッグパネル表示切替 |

デバッグパネルは、上に状態表示・STOP / E-STOP・ロボットの切り替え（Mock / 実機）が常に出て、その下がタブに分かれる。パネルのボタンやスライダーはキーボードのフォーカスを取らないので、Space（停止）と矢印キーは常にゲームに届く。

| タブ | 中身 |
|---|---|
| 実機 | 上から順に: 1. 準備（モーター有効・アラーム解除）、2. 巻き上げ（押している間だけ動く ▲ / ▼、巻き上げ点（上）/ 下げ点（下）の記録とやり直し、いまの Z と基準、速さ）、3. 原点復帰（アームを巻き上げてから）、4. 爪（下の節）、5. 自動キャッチ、位置を指定して移動（X / Y / Z スライダー、折りたたみ） |
| ジェスチャー | ON/OFF、マウスでの模擬、向きの反転、状態表示。感度・速度・ROI は折りたたみ |
| カメラ | 2 台の全画角表示とカメラの割り当て、スコープ |
| 見た目 | FPS・物理演算時間、ロープ物理・投影・エフェクト/音（折りたたみ）、表情の固定と結果イベント |
| モック | Mock 切断/再接続、速度・加速度・通信レート、テストシナリオ |
| ログ | ゲーム・バックエンド・シリアル（TX / RX、POS の定期報告は省く）のログ。最後の 6 行はどのタブでもパネル下に出る。「ログをコピー」で、そのときの状態と全ログをクリップボードへ（不具合の報告に貼る） |

細かくは: 仮想 XYZ 目標、XYZ ランダム同時移動、モック速度・加速度・通信レート、重力・減衰・UFO 質量・セグメント数・反復回数・ロープ巻き取り速度・最短/最長・揺れ誇張、カメラ俯角・奥行き倍率・XY 表示倍率・ロープ太さ・ピクセルスケール、表情の固定、Mock 切断/再接続、FPS と物理演算時間、テストシナリオ 1〜10 + 掴みサイクル。USB カメラ 2 台（俯瞰 / アーム先のフォーカス）の全画角表示と、どのカメラをどの役割に使うかの選択。

### 爪（2 つ目のサーボ）のテスト

デバッグパネルの「実機」タブ「3. 爪（サーボ 2）」で、爪のサーボ（STS3020、ID 2）を少しずつ回して、開き・閉じの角度を探せる。

- −10° / −1° / +1° / +10° のボタン、または `[` / `]` キー（ステップはスライダーで 0.5〜30°、既定 5°）。1 回は最大 ±90°
- 「arm_zero」でいまの角度を 0° にする。以後は 0° からの角度が表示されるので、開き・閉じの角度をメモできる（arm_zero の前は 1 回転の中の角度 0〜360° を表示）
- 実機では `SERVO_TURN 2 <回転数>`（いまの位置からの相対回転）を送り、動いた後に `SERVO_STATUS 2` で角度を読み直す。初回は `TEST_MODE ON` も送る。モーター有効（enable motors）が必要、原点復帰は不要。ほかの移動中は受け付けない
- 絶対角の `SERVO_ANGLE` は、近いほうへ回るので可動範囲の限られた爪では逆回りしてストッパーに当たる恐れがあり、使っていない
- ゲーム内の MockRobot でも、同じ操作で角度の表示が変わる

**開き・閉じの角度を記録する**

1. 少しずつ回して爪が閉じた所で「ここを閉じ位置に」
2. 少しずつ回して爪が開いた所で「ここを開き位置に」（閉じ位置から回した向きが「開く向き」として記録される）
3. 以後「閉じる」「開く」（キーは A / Q）でその角度へ回る。両方を記録すると、掴む / 離す（`grab`）も `arm_open_turns` の代わりにこの角度を使う

- 記録はバックエンドが `config/arm_calibration.json` に保存し、次に起動したときも使う（残したければコミットする）。保存するのはサーボの 1 回転の中の角度（電源を入れ直しても変わらない）と、閉じ→開きの符号付きの幅
- 回るのは閉じ〜開きの間だけで、ストッパーのある側へは回らない。少し外れた位置からは近いほうの端を通って戻る
- 片方だけ記録し直したときは、前の開く向きを保つ。初めての記録は、同じ起動のうちに両方を記録する（そうでないと短いほうの回り方を開く向きと見なす）

### ピクセル VFX（pixelfx）

ゲームの場面に合わせて、[pixelfx](https://github.com/patch-gg/pixelfx)（MIT）で作ったピクセルアートの演出を出す。

| 場面 | 演出 |
|---|---|
| ゲーム開始（実機・Mock とつながって準備完了） | 3・2・1・GO! のカウントダウンと、UFO のエネルギー起動 |
| 待機中 | UFO の上の弱く光るリング |
| 移動中 | （UFO 自身の小さな粒子。追加の演出はなし） |
| アームが下がっている間 | UFO に集まるエネルギー |
| 爪を閉じた瞬間（実機が閉じたと返したとき） | 小さな光のバースト |
| 成功（G キー、または景品の検出） | 紙吹雪とキラキラ |
| 失敗（F キー、または景品の落下の検出） | UFO の下の小さな煙 |
| ラウンド終了 | シアンの粒が散って消える |

- 成功・失敗は、明示のイベント（G / F キー、映像の検出）だけで出す。アームの動きから推定はしない。同じ場面の演出は 1.5 秒以内には繰り返さない（通信の重複や揺れで多重に出ない）。
- デバッグパネル（F1）の「VFX」タブで、全エフェクトの再生（速度・拡大・位置・ループ）と、各場面の模擬再生ができる。実機がなくても確認できる。`config/game_config.json` の `render.vfx` を false にすると全部止まる（ゲームはそのまま動く）。
- 絵は `game/assets/vfx/`（`catalog.json` に一覧）。作り直しや追加は、pixelfx をリポジトリの外に取得して `python3 tools/build_vfx.py --pixelfx <pixelfx のフォルダ>`（Node は生成のときだけ）。手順と注意はスキル `.claude/skills/pixelfx-vfx/SKILL.md`、ライセンスは `game/assets/vfx/LICENSE-pixelfx.txt`。

### USB カメラとスコープ

- カメラは 2 台。**俯瞰カメラ**（机の上を見下ろす。ハンドジェスチャーの認識にも使う。C270）と、**フォーカスカメラ**（アームの先。Innomaker U20CAM）。`config/game_config.json` の `camera.overview.match` / `camera.focus.match` にカメラ名の一部を書くと自動で割り当てる（デバッグパネルでも選べる）。初回は mac のカメラ許可を求められる。
- 横移動が止まって少し静止したとき、アームの上下中、`LOWERING` 中に、UFO が望遠鏡を覗くポーズをとり、UFO の右隣（右に余裕がなければ左隣）に丸いスコープが開く。中身はフォーカスカメラ（無ければ俯瞰カメラ、どちらも無ければ砂嵐）。横に動き出すと閉じる。`camera.scope.*` で秒数やズームを変えられる。
- 映像は画面に描くだけ。保存も送信もしない。スコープの映像は実機の制御に使わない（ジェスチャー認識は下記）。

### ハンドジェスチャー・ジョイスティック

親指と人差し指をつまむと、**つまんだ位置が中心の仮想ジョイスティック**になり、手を前後左右に動かした分だけクレーンの XY が**速度で**動く。指を離すと止まる。UFO とロープはこれまでどおり実機（Mock）の状態から物理で描く（手の位置で UFO を動かすことはしない）。

```bash
./start.sh gesture                      # Python の MockRobot + C270 で認識 + ゲーム（ジェスチャー ON）
./start.sh game --gesture-demo          # カメラなし: 決まった手の動きを流してゲーム内 Mock を操縦
./start.sh real /dev/cu.usbserial-XXXX --gesture   # 実機（ゲームもジェスチャー ON で起動。enable motors → home の後に操縦）
```

- 初回は `backend/models/hand_landmarker.task`（MediaPipe の公式モデル、Apache-2.0、約 7.8 MB）を自動でダウンロードする。依存は `uv sync --extra vision --extra hands`（`start.sh` が `--gesture` を見て入れる）。
- ゲーム内の MockRobot でもカメラ操作を試せる: `./start.sh backend --mock --gesture` を別に起動し、`./start.sh game` で H を押す（ゲームはバックエンドからジェスチャーだけを受け取る）。カメラが無ければデバッグパネルの「Sim hand (mouse)」で、プレイ画面上のマウス（左ボタン = 手のひら上でつまむ（XY）、右ボタン = 手のひら下でつまむ（上下））が手の代わりになる。
- 操作: H で ON → 手をカメラに見せる → つまむ（「操縦開始！」）→ 手を動かす方向に進む（中心に戻すと止まる）→ 離すと止まる。手を動かせる範囲が足りなくなったら、離して手を戻し、もう一度つまむ（クラッチ）。クレーンの位置はそのまま。
- 止まる条件（どれも速度を即ゼロにし、**指を離して新しくつまむまで再開しない**）: 指を離す、手を見失う・手が 2 つ写る（素早い動きのブレで一瞬見失うことがあるので `gesture.lost_grace_ms` = 300 ms までは直前の状態で続ける）、認識イベントが `gesture.stale_ms`（350 ms）より古い、カメラが外れる、WebSocket が切れる、ゲームのウィンドウが非アクティブ、Space、アラーム、キーボード操作（キーが優先）、ジェスチャー OFF、実機の準備ができていない。認識が途切れたときなどは、ゼロ JOG に加えて減速停止（`soft_stop`）も送る。
- 実機の条件: 接続済み・モーター有効・原点復帰済み・アラームなし・ほかの移動コマンドが動いていない。ジェスチャーがホーミングやモーター有効化を始めることはない。`gesture.allow_real_robot` が false なら実機ではジェスチャーで動かさない（Mock での確認後、true にした）。
- 実機を止める仕組み: ファームウェアと Mock は最後の JOG から 250 ms で止まる。加えてバックエンドは、JOG を送っていたクライアントが切断したときと、JOG の更新が 300 ms 途絶えたとき（ゲームが固まった）にゼロ JOG を送る。**カメラによる接触・挟み込みの検出は安全機能ではない**。手をクレーンの可動範囲に入れない運用と、物理的な非常停止を前提にすること。操作領域を可動範囲の外に限るには `gesture.roi` / `roi_enabled`（デバッグパネルでも調整可）。
- ゲーム画面左下の HUD に、ジェスチャー用カメラの小さなライブ映像と、手のひら中心（灰 / 水色 / 金 = 未検出 / 検出 / つまみ中）・スティックの輪を表示する。手が画角の端（10% 以内）に近づくと枠が黄色に、端から外へ出て見失うと赤く点滅して「カメラの外に出たよ」と、戻す方向の矢印を出す。
- デバッグパネルの俯瞰カメラの映像に、検出状態を重ねて表示する: 手のひら中心（灰 = 未検出、水色 = 検出、金 = つまみ中）、つまんだ中心とスティックの輪、ROI、状態の 1 行。手の骨格はバックエンドを `--gesture-landmarks` 付きで起動したとき（`./start.sh gesture` は付ける）。
- 効果音: パーの手を検出したら小さく「ポン」（0.6 秒に 1 回まで）、つまみを検出したら「ピポッ」、ピンチをやめて手を開いたら「ポピッ」、操縦が途切れたら（見失い・2 つの手・期限切れ・カメラ外れ・切断）「ブブー」。ゲーム内で合成する 8bit 風の音で、`audio.cue_pinch` / `audio.cue_lost` に mp3 のファイル名を書けば差し替えられる。
- 手の形と操作:

  | 手の形 | 操作 |
  |---|---|
  | 手のひらを上に向けて、つまんで動かす | XY |
  | 手の甲を上に（手のひらを下に）向けて、つまんで動かす | アームの上下（つまむと XY とは違う「ポピポピ」という音）。ジェスチャー用カメラの映像（画面に出ている向き）で手を上へ動かすと上げる、下へで下げる。速さは `gesture.joystick.max_speed_z`（15 z/s）。逆なら「Invert Z」（`invert_z`） |
  | グーを 0.5 秒 | 爪を閉じる（A と同じ。記録した閉じ位置へ） |
  | ピースを 0.5 秒 | 爪を開く（Q と同じ） |

  つまむのは親指と、人差し指・中指・薬指のどれでもよい（つまみ始めに親指に一番近い指。離すまで変わらない）。手のひらの向きはつまんだ瞬間に決まり、離すまで変わらない。手を横に立てて向きがはっきりしないときは XY。向きは手首・人差し指の付け根・小指の付け根の並び（映像上の回り方）で見ていて、右手が前提。左手で使うときや逆に出るときはデバッグパネルの「Swap palm」（`gesture.palm_invert`）。グーとピースは、つまみ中でなく、手が見えていて、実機の準備ができている（上の条件）ときだけ。一度動いたら、別の手の形にするまで同じ形では再び動かない。グーやピースのときはつまみを始めず、つまみ中にグーやピースにすると、そのつまみは終わる（握り込みの途中でつまみと見なされて動き続けないように）。指が畳まれているかは「指先が第 2 関節より手首に近いか」で見ている（カメラから見た向きによっては誤判定がありうる）
- 向きの合わせ方: 手を右へ動かして UFO が左へ行くなら「Invert X」、奥 / 手前が逆なら「Invert Y」、前後と左右が入れ替わっていれば「Swap XY」（デバッグパネル）。決まった値は `gesture.joystick.invert_x` などに書く。今の C270 の取り付けでは `invert_x` / `invert_y` とも true。
- 表示の向き: C270 の映像は上下左右に反転して表示している（`camera.overview.flip_h` / `flip_v` = true）。HUD の輪の四角と矢印は、この表示の上の手と同じ向きに動く（クレーンの向きは上の invert で決まり、表示の反転とは別）。
- 止まった理由: 操縦が終わるたびに、ゲームを起動したターミナルに `gesture: ACTIVE -> WAITING_RELEASE (no_hand)  hands 0 pinch_ratio … latency …` のような行が出る。デバッグパネルの Log にも出る。
- 主な初期値（`config/game_config.json` の `gesture`）: ピンチ開始 1.0 / 解除 1.5（指先の距離 ÷ 手の大きさ = 人差し指〜小指の付け根の幅と 0.75 × 手首〜中指の付け根の長さの大きいほう。C270 で手で調整した値。つまんでいた指がまっすぐ伸びていれば、比率が開始の 1.0 を超えた時点でも解除する。普通のパーは比率 1.0〜1.3 くらいで、1.5 には親指を大きく広げないと届かないため）、確定 0 ms、見失いの猶予 300 ms（素早く動かした手のブレ対策）、MediaPipe の追跡の信頼度 0.3（いずれもデバッグパネルのスライダーで、動かしながら調整できる）、スティック半径 = 画像短辺の 15%、デッドゾーン 12%、最大速度に達する位置 80%、最大 30 mm/s、カーブ 1.5 乗、スムージング 80 ms、期限 350 ms、ARMED の表示 120 ms。認識は GPU（Metal）で行う（`gesture.delegate`。CPU だとゲームと CPU を取り合って認識が途切れやすい）。MediaPipe 1.1.1 の GPU 処理は 1 フレームごとに画像 1 枚分のメモリを抱え込み、約 8 分で「Error creating pixel buffer: -6662」で異常終了するので、`gesture.gpu_recreate_s`（10 秒）ごとに認識器を裏で作り直して入れ替える（入れ替えの間も認識は止まらない）。
- 操作方式の切り替え: ゲームが手をどう読むか（つまみ・手の形など）は「方式」として分けてある（`gesture.scheme`。`pinch_joystick` = 上のつまみジョイスティック（既定）、`pose_direction` = 手の形で移動）。デバッグパネルの Gesture タブの「Scheme」か、起動時の `--gesture-scheme pose_direction` で切り替える。止まる条件・ラッチ・実機の条件・キーボード優先などの安全の仕組みは方式によらず共通（`game/scripts/input/gesture_control.gd`）。方式を足すときは `GestureScheme`（`game/scripts/input/gesture_scheme.gd`）を継承し、`GestureControl.make_scheme` と `SCHEME_IDS` に登録する。方式ごとの設定は `gesture.schemes.<方式名>`。方式を切り替えると必ず停止し、操縦の合図をいったんやめるまで再開しない。
- 手の形で操縦（`pose_direction`）: 手の形を見せている間、決まった向きに一定の速さで動く。手の位置は関係ない。既定の割り当て:

  | 手の形 | 操作 |
  |---|---|
  | 指差し（人差し指だけ伸ばす） | 指の向きへ移動（XY。斜めも） |
  | いいね（親指だけ立てる）で親指が画面の上向き | アームを上げる |
  | いいねで親指が画面の下向き | アームを下げる |
  | パーを 0.5 秒 | 爪を開く |
  | チョキを 0.5 秒 | 爪を閉じる |
  | グー | 何もしない（手を休める形） |

  対応は `gesture.schemes.pose_direction.directions`（実機の軸で `[x, y, z]`、+X 右・+Y 奥・+Z アーム上げ。`"finger"` なら指の向き。キーは手の形の名前 `open` / `peace` / `fist` / `point` と、いいねの `thumb_up` / `thumb_down`）と `claw`（爪を動かす形）、速さは `speed_mm_s`（20 mm/s）/ `speed_z`（10 z/s）。
  - 指差し: 人差し指の付け根から指先への向き（カメラ映像の上での向き）に動く。斜めも含めてどの角度でもよく、指を回せば動く向きもついてくる。映像の向きから実機の軸への直し方は、つまみジョイスティックと同じ `gesture.joystick.invert_x` / `invert_y` / `swap_xy`（向きが合わなければデバッグパネルの Invert X / Y・Swap XY）。8 方向などに丸めたいときは `point_snap_deg`（45 で 8 方向。0 = 丸めない）。指をカメラに向けて短く見えるとき（手の大きさの `point_min_len` = 0.4 倍未満）は向きが分からないので動かない。
  - いいね: 上下は**画面に出ているカメラ映像での**上 / 下（つまみの上下モードと同じ。カメラは机を見下ろしているので、親指を天井や机に向けるのではなく、手を寝かせたまま親指を画面の上 / 下へ向ける）。親指が横向き（垂直から 60° 以上。`thumb_min_vertical`）のときは動かない。逆なら「Invert Z」。上から下へ向きを変えると一度止まってから下げ始める。
  - 手の形が `pose_confirm_ms`（150 ms）続いたら動き始める（別の形へ変える途中で一瞬通っただけでは動かない）。動いている間は `pose_release_ms`（150 ms）より短い形のちらつきでは止まらない。
  - 別の形に変えると一度止まり、改めて動き出す（逆向きへいきなり反転しない）。
  - 強制停止（見失い・Space・キーボード・方式の切り替えなど）の後は、同じ形のままでは動かない。別の形（移動に使う形でもよい。パーで止められたらチョキへ、など）に `pose_release_ms` 以上変えると解除される。1 フレームだけの誤判定では解除しない。
  - 移動に使う形は爪の操作には使わない（設定で重なっていたら爪のほうを外して警告する）。パーを 0.5 秒見せると爪が開き、チョキで閉じるので、手を休めるときはグーにする。
  - 手を見せただけで動くので、手をカメラに向けるときは注意。止まる条件と実機の条件はつまみ方式と同じ。
  - マウス模擬（「Sim hand (mouse)」）では、1 / 2 / 3 / 4 / 5 キーを押している間がパー / チョキ / グー / 指差し / いいね（指と親指の向きは画面の中心からマウスへ）。カメラなしの `./start.sh game --gesture-demo --gesture-scheme pose_direction` は、指差し（指が一周する）→ いいね上 → いいね下 → パー → チョキ → グー → 画角の外、を繰り返す。
  - 実カメラ・実機では未確認。バックエンドの手の形の判定（指先が第 2 関節より手首に近いか）は、カメラから見た向きによって誤判定がありうる。指差しは「人差し指だけ伸びていて、中指・薬指・小指が畳まれている」（親指は見ない）。いいねは「4 本の指が畳まれていて、親指の先が中指の付け根から手の大きさの 0.85 倍より離れている」（親指を指の上にしまっていればグー）。バックエンドは検出した手ごとに `point_dx` / `point_dy`（人差し指の向き）と `point_len`、`thumb_dx` / `thumb_dy`（親指の付け根から先への向き）を送る。つまみ方式では、いいねもグーと同じく爪を閉じる（今までグーと判定されていたため）。

## Phase 2: 実機（バックエンド経由）

```bash
cd backend
uv sync                      # 基本（pyserial, websockets, numpy）
uv run pytest                # 31 テスト（ファームウェア応答を模した FakeFirmware で検証）

uv run corexy-ufo-backend --mock                 # 実機なし。WebSocket だけ立ち上げる
uv run corexy-ufo-backend --list-ports
uv run corexy-ufo-backend --port /dev/cu.usbserial-XXXX
```

Godot 側はデバッグパネルの「Robot source」を **WebSocket backend** に切り替えるか、`-- --source websocket` で起動します。
接続後の手順（安全のため起動時はモーター操作無効）:

1. 「実機」タブの `モーター有効`（アーミング）
2. **原点復帰より先に巻き上げを合わせる**（アームが下がったまま XY を動かすとぶつかるため）。アームを最上位に合わせて（▲ か W で上げる）「ここを巻き上げ点（上）に」（`z_set top`、旧 `z_zero` と同じ。Z 基準。ファームウェアに Z ホーミングはない）。
   - 初回は続けてアームを一番下まで下げ（▼ か S）、「ここを下げ点（下）に」（`z_set bottom`）。上と下の 2 点のサーボのカウント差から、Z 1 単位あたりのカウント（`z_counts_per_unit`）とドラムの回転の向き（`z_sign`）を測り、`config/z_calibration.json` に保存する（設定ファイルの値より優先。自動キャッチの検査も同じ値を使う）。2 点が半回転より近いときは記録しない。
   - 上と下を測るまでは、▲ / ▼ が Z 0〜100 で止まらない（設定の換算は推測なので、本当の上 / 下まで動かせるように。押している間だけ動くので見ながら操作する）。測った後は 0〜100 で止まる。測り直すときは「Z の上下をやり直す」（`z_set clear`。記録と保存した実測を消す）。
   - 次回からは、電源を入れ直しても上か下の 1 点を記録するだけでよい（カウントはファームウェアの起動ごとに振り直されるので、記録した点はファームウェアの再起動・再接続で消える）。
   - 最後にアームを一番上まで巻き上げる。
   - **巻き上げサーボだけ電源が切れた（切った）とき**: サーボは 1 回転分しか動けない状態に戻り、ファームウェアはそれに気づかない。そのまま ▲ / ▼ を押しても途中（1 回転の端）で黙って止まる。バックエンドはサーボの状態報告（`tracking=YES` なのに `limits` が `0/0` でない）からこれを検知し、「実機」タブに警告を出す。検知中は Z の JOG を拒否し、ドラムの回転数が分からなくなるので記録した点も消す。「巻き上げサーボを復帰」（`z_servo_recover`）を押すと、ファームウェアがサーボを何回転でも回せる設定に戻す準備をする（動かさずに拒否される `SERVO_TURN 1 0.01` を 1 回送る）。そのあと ▲ / ▼ を押せば動くので、上下の点を記録し直す。ファームウェア側で自動で直す修正は [docs/HANDOFF_FIRMWARE_Z_SERVO.md](docs/HANDOFF_FIRMWARE_Z_SERVO.md) で依頼し、CoreXY_UFO #11 で入った。**新しいファームウェアでは「復帰」は要らない**: サーボの状態報告が `tracking=LOST` になり、警告は出るが ▲ / ▼ はそのまま押せる。最初の押下でファームウェアが多回転に設定し直し（`JOG servo id=1 ... tracking=RESET`）、警告が消える。回転数は消えているので、上下の点は記録し直す。爪（サーボ 2）も電源が共通なので同時にリセットされ、爪の 0° 基準と記録のカウントは消える（記録した角度は残る。最初の `arm_step` は動かずに拒否されるので、もう一度押す）。
3. `原点復帰 (home)`（`HOME` → `HOME complete` 待ち）。実機は Z の基準があり、アームが巻き上げ点の近く（`backend.home_z_tolerance` = ±5）にあるときだけ受け付ける（`backend.home_requires_z_top`、既定 true）。
4. 「位置を指定して移動」の X / Y / Z スライダー → `XY` / `SERVO_TURN 1` が送られ、`ACK`/`NACK` がログに出ます
5. `E-STOP` → `ABORT`。以後は `clear_alarm` と `home` が必要です

```json
{"type":"command","request_id":"g12-3","data":{"name":"move_xy","params":{"x":120,"y":80}}}
{"type":"ack","request_id":"g12-3","timestamp":1730000000100,"data":{"command":"move_xy","x":120.0,"y":80.0}}
```

## 設計の要点

- **ロープ物理**（`game/scripts/physics/rope_simulator.gd`）: 3D Verlet + 距離拘束（PBD）。上端は実機 XY から決まる可動アンカー、下端に UFO 質量。1 tick を 16 サブステップに分け、各サブステップで全セグメントを三重対角の直接解法で一度に拘束し、長距離拘束（アンカーからの距離 ≤ 弧長）で伸びない。ロープ長変更時はアンカー中心に形状をスケーリング（巻き取り）。
- **投影**（`projection.gd`）: 固定カメラを X 軸まわりに俯角回転 → ピンホール分割。ロープ全質点と UFO が同じ関数を通る。
- **Z 逆マッピング**（`robot_state.gd: rope_length_for_z`）: アーム最上位 → ロープ最長 → UFO 最下位。
- **状態分離**: `RobotState`（実機/モックの物理状態） と `GameState`（演出状態、イベント駆動）。物理演算結果は実機に送らない。
- **安全**: 起動時モーター無効、`enable_motors` 必須、ホスト側ソフトリミット、`stop` は常時受付、`request_id` 重複排除、応答タイムアウト、切断検知。ファームウェアの安全機構は変更していない。

## 既知の制約

- ファームウェアは移動中に位置を返さないため、移動中の XY は推定値（`measured:false`）。
- ファームウェアにホストウォッチドッグがなく、USB 切断時に実機が自動停止しない（docs/test_report.md 参照）。
- Z はサーボ絶対カウントの相対値で、巻き上げ点（上）か下げ点（下）の記録をファームウェアの起動ごとに行う必要がある（2 点で測った換算は保存されて残る）。
